# health-export-check

![tests](https://github.com/xdso0/health-export-check/actions/workflows/tests.yml/badge.svg)

보건의료 연구 결과파일을 **기관 밖으로 내보내기 전에** 개인 식별 위험이 남았는지 찾아 주는 점검 도구입니다.
표(csv·xlsx·rds), 문서(docx·txt), 이미지, 영상, DICOM을 한 번에 봅니다.

```
python export_check.py 결과폴더/
```

```
■ 결과폴더/table2.xlsx
  (Sheet1) [위반] 소수 셀 (1~2명) 2건 [환자수] (행 5, 9) — 설정 min_cell=3, 억제·병합
  (Sheet1) [주의] 합계 행 1건 (행 12) — 합계에서 빼면 억제한 셀이 복원되는지 확인(2차 억제)
■ 결과폴더/figure3.png
  (픽셀) [위반] 전화번호 형식 1건 [이미지 화면 속 글자] (줄 2) — 부록8-4 연락처
■ 결과폴더/ct_0001.dcm
  (헤더) [위반] DICOM 환자 이름 [PatientName] — DICOM PS3.15 Annex E 제거·대체 대상
```

**셀 값은 출력하지 않습니다.** 규칙 이름, 열·위치, 건수만 보여 줍니다. 점검 결과 화면이 또 다른 유출 경로가 되지 않게 하기 위해서입니다.

> 이 도구는 의심 항목을 찾아 주는 보조 도구입니다. 반출 가능 여부는 기관 데이터심의위원회(DRB)와 개인정보보호책임자가 판단합니다.

### 오탐을 줄인 방법
- 주민번호는 앞 6자리가 **실제 날짜**이고 7번째 자리가 1~8일 때만, 카드번호는 **Luhn 검증**을 통과할 때만 잡는다
- 숫자 앞뒤가 숫자·영문이거나 **소수의 일부**(`0.9001011234567`)면 잡지 않는다. 문장 끝 마침표는 허용
- 날짜는 구분자가 앞뒤로 같아야 한다(`2024-03-15`, `20240315`). 금액 `201301.12`, UUID 속 숫자열은 날짜가 아니다
- `코드·CODE·EDI·ATC` 열과 UUID 열은 숫자 형식 검사에서 뺀다 (EDI 같은 9자리 코드가 전화번호로 잡히는 문제를 막으려고)
- 성명은 **한국인 성씨**로 시작하고 `외래 환자`, `해당 환자` 같은 일반어가 아닐 때만

## 내가 결정한 것

**셀 값을 출력하지 않는다.** 점검 도구가 "010-1234-5678 발견"이라고 화면에 찍으면, 그 화면과 로그가 새 유출 경로가 된다. 그래서 규칙 이름, 열, 행 번호, 건수만 내보낸다. 사람이 확인할 때는 행 번호로 원본을 찾아 가면 된다.

**소수 셀 기준(k)을 코드에 박지 않았다.** 공개 가이드라인에는 "몇 명 미만이면 억제"라는 수치가 일률적으로 정해져 있지 않고, 기관마다 데이터심의위원회가 정한다. 예시값 3을 코드에 박으면 그 숫자가 기준처럼 쓰일 위험이 있어서 설정 파일로 뺐다.

**숫자 형식은 '그럴듯함'까지 확인한다.** 주민번호는 앞 6자리가 실제 날짜여야 하고, 카드번호는 Luhn 검증을 통과해야 한다. 통계 결과표에는 `0.9001011234567` 같은 긴 소수, EDI 9자리 코드, UUID 가 흔한데, 형식만 보면 이것들이 주민번호와 전화번호로 잡힌다. 실제로 공개 데이터 검증에서 금액(`201301.12`)이 날짜로, UUID 가 전화번호로, `ENCOUNTERS` 열이 집계 열로 잡히는 오탐이 나와서 숫자 경계와 열 판별 규칙을 고쳤다.

**성명 탐지는 성씨와 예외어 목록을 같이 쓴다.** "○○ 환자" 패턴만 보면 "외래 환자", "해당 환자", "신규 환자"가 전부 사람 이름이 된다. 한국인 성씨로 시작하는지 보고, 일반 명사 목록(`NOT_NAMES`)을 따로 두어 걸렀다.

**OCR 각도 보정을 껐다.** 켰을 때 똑바른 숫자 줄(`010-1234-5678 검사값 0.9001…`)을 뒤집힌 글자로 오인해 엉뚱한 문자열로 읽었다. 결과파일 그림은 대부분 똑바로 놓여 있어서 끄는 쪽이 탐지율이 높았다.

**라이선스 문제가 없는 것만 쓴다.** R 파일 리더로 처음 쓴 pyreadr 가 AGPL 이라 MIT 인 rdata 로 바꿨다. 얼굴 탐지는 Haar 대신 OpenCV 공식 YuNet(MIT)을 썼다. 문신을 찾는 공개 모델은 라이선스까지 깨끗한 것을 찾지 못해 넣지 않았다.

**검증은 정답을 심어 놓고 잰다.** 공개 데이터에 가짜 식별자를 일부러 넣고 몇 개를 잡는지(검출률), 아무것도 없는 표에서 몇 번 잘못 경고하는지(오탐)를 같이 본다. 하나만 보면 "다 잡는다"와 "다 경고한다"를 구별할 수 없다.

## 한계 (솔직하게)

- **문신·흉터는 자동으로 찾지 못합니다.** 라이선스 문제없이 쓸 수 있는 공개 탐지 모델이 마땅치 않습니다. 대신 피부색 영역이 넓은 사진을 "사람이 확인할 것"으로 표시하는데, 피부색과 비슷한 물체(커피, 고양이 털, 조직 염색 슬라이드)도 걸려서 '참고' 등급으로만 냅니다
- OCR은 글자가 빽빽한 배경 위의 글자, 기울어진 글자, 손글씨에 약합니다
- 영상의 **음성**과 컨테이너 메타데이터(촬영기기·위치)는 보지 않습니다
- 영문 성명은 열 이름으로만 잡고, 값만 보고는 잡지 않습니다
- 희귀질환은 질병관리청 목록 CSV를 설정에 넣어야 판별합니다
- 수치 기준(k 등)은 공개 가이드라인에 일률적으로 정해져 있지 않아 설정값입니다. 예시값을 그대로 쓰지 말고 기관 기준으로 바꾸세요

## 설치와 실행

```bash
pip install -r requirements.txt          # 표·문서만 볼 때는 앞의 4개면 충분
python export_check.py 결과파일.xlsx
python export_check.py 결과폴더/ --config rules.example.toml
python export_check.py 환자단위.csv --qi 성별,연령대,시군구
python -m pytest                         # 단위 시험
```

종료 코드: 위반이 하나라도 있으면 1 (배치·CI에서 반출 차단용).
얼굴 탐지 모델은 첫 실행 때 `~/.cache/health-export-check/` 에 한 번 내려받습니다.
